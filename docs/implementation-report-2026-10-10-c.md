# Implementation report: touch input (Lattice 0.36.0, 2026-10-10)

The report of 0.35.0 and 0.35.1 is in `archive/implementation-report-2026-10-10-b.md`.

Olivier's request: the defense deck's mobile copy is made by a script after the build (`phd_defense` project, `scripts/mobile-deck/make_mobile.py`), which appends a touch layer that turns gestures into synthetic key presses. Lattice should support phones natively, and the mobile navigation must appear only on mobile. Decisions taken with him before the work: laptops with a touchscreen stay out (better a corner case without touch navigation than controls cluttering a screen that does not need them); gestures configurable in the front matter in this release; both a front matter switch and a URL override, with a warning when they conflict and one of them winning; tour and start buttons in the help sheet.

## 1. What was built

- **Touch mode** (`runtime/lattice.js`, section "touch input"): on when `(hover: none) and (pointer: coarse)` matches (phones, tablets), following the query when it changes. `?touch` forces it on and `?touch=0` off. `touch: false` in the front matter turns it off; the URL wins over it (the viewer asks at view time, the author decided for every viewer), with a console warning and a flash. Passive windows never enter it. In touch mode the root has the class `lt-touch`, which scopes every style (`touch-action: none` on `#lt-stage`, no overscroll, no text selection); the controls are created on first use, so a desktop page has the same DOM and look as before.
- **Gestures**: the gestures of the script, with the same thresholds (45 px swipes within 900 ms, 12 px and 400 ms taps, 550 ms long press, 320 ms and 40 px double tap), plus two unbound ones (`two-finger-swipe-up`, `two-finger-swipe-down`). They call actions through `perform`, the entry point now shared with `onKey` (playback stop, checkpoint anchor), so rebinding keys never breaks them. The input rules of the core apply: a gesture begun over an enlarged element only closes it; while the overview or the go-to is open, only a gesture bound to `overview` or `goto` acts, and closes it. A tap on a link, badge, branch option or enlargeable block is not counted as the first half of a double tap. The script's fixes are kept: `preventDefault` on `touchmove` (history swipe, bounce), the click after a gesture cancelled, a fresh gesture on every single-finger `touchstart` (lost `touchend`), gestures ignored while pinch-zoomed.
- **Controls**: Notes (absent in presenter view) and **?** buttons; a notes sheet that follows every render (rather than polling) and renders math; a help sheet listing the deck's gestures with the labels of the presenter's keybindings, with a **Tour** button (cycles tours, shown when the deck has tours) and a **Start of the deck** button (HOME) above the list; a short notice naming each gesture's action. The help opens by itself once per browser (`lattice:touch-help-seen` in `localStorage`, one key for all decks, so a rebuild does not show it again).
- **Front matter** (`model.py`, `parser.py`, `emit.py`): `touch` (bool, default `true`) and `gestures` (gesture to action name, `none` or null), with the aliases of `keys`; an unknown gesture or action is the new error LT066. The deck JSON carries `touch` and `gestures` (the gestures that have an action).
- **Page**: the viewport meta has `viewport-fit=cover`, and `#lt-root` is inset by the safe areas (`env(safe-area-inset-*)`, zero on a desktop).

## 2. Tests and verification

- `tests/test_touch.py` (new, Chromium): every default gesture in an emulated phone held sideways, the help sheet once with its buttons, the notes sheet with math following the slide, a link tapped, a swipe over the open overview; no class and no controls on a desktop, and on an emulated touchscreen laptop where touches do nothing, then the switch when the query changes; `?touch`, `?touch=0`, `touch: false` and the warning; the presenter window without Notes; passive windows; `gestures` with rebound keys; gestures over an enlarged block. `test_parsing.py` (LT066) and `test_output.py` (deck JSON, viewport meta) cover the build side.
- Found while testing: `pointerdown` comes before `touchstart`, so a swipe over an enlarged block closed it and then navigated; the press is now remembered (`pressOverZoom`). Chromium's touch emulation reports a coarse pointer even without `is_mobile`, so the touchscreen laptop is emulated by answering the media query from the page.
- `pytest -rs`: 467 passed, 1 skipped (Firefox, not installed here), 1 failed: the manual's `plot-sources` in `test_layout.py`, as since 0.34.0 (section 3); it fails the same way without this change. Examples and the manual rebuilt; screenshots of the help and notes sheets in an emulated phone (both orientations) and of the manual's new `touch` slide and its front matter slide checked; `scripts/check_docs.py`: 0 problems.
- Docs: spec 2.2, 7.6, 7.8 (new), 11.1, 11.2, 12 and 15; README (gestures under Navigation); design report (section 3.17, decision 46, roadmap); `docs/USER_SKILL.md` (feature map, a rule that bites); `docs/SKILL.md` (structure, invariants, suites, a pitfall); the manual (`touch` slide, front matter row, quick tour); version 0.36.0. The `plot` change listed as unreleased in spec 15 ships with this version.

## 3. Left open

- Only Chromium's mobile emulation was available; a real iPhone (Safari honours `touch-action` partly) and a real Android phone are untested.
- The HUD is part of the scaled slide, so on a phone held upright its text is very small; holding the phone sideways (the help says so) gives the largest slide.
- The `plot-sources` layout failure of 0.34.0 in this sandbox (fonts) is unchanged.
