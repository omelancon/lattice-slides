# Implementation report: notes written while rehearsing (Lattice 0.37.0, 2026-10-10)

The report of 0.36.0 is in `archive/implementation-report-2026-10-10-c.md`.

Olivier's request: write presenter notes in the presenter view while rehearsing with `lattice serve`, saved to a sidecar `FILENAME.notes.md` by slide id; the deck's own `::: notes` stay and cannot be edited there (static notes); `lattice build` brings the sidecar notes in, so the built HTML holds all notes as static notes. Decisions taken with him before the work: sections `# slide-id`; in the built output the sidecar notes simply follow the static ones and look the same (only editability differs, and only under `serve`); autosave; an unknown id is a warning.

## 1. What was built

- **The sidecar** (`notes.py`, new): `talk.notes.md` beside `talk.md`, cut into sections by lines `# ID` outside fenced code; text before the first section is kept and ignored. `Sidecar.set` rewrites one section and keeps every other byte (the preamble, the other sections, orphans); a new section goes before the first section of a later slide in document order, else at the end; empty notes remove the section; the sections of an id given twice become one; `save` writes atomically (a temporary file renamed over it) and removes a sidecar left empty.
- **One renderer** (`render_section`): Markdown, math, wiki links and code blocks, as static notes show them; containers and directives are reported (LT068) and their content shown without them; components are shown as code (LT068). Build and serve use it, so the notes look the same rehearsed and built.
- **Build** (`build.py`, `notes.merge_into`): after the bodies and before graph resolution, each section is appended to its slide's static notes; its wiki links create link edges (an unknown one is LT011, as in static notes). New warnings: LT067 (a section whose id is no slide, kept in the file and ignored; an id with several sections) and LT068 (what notes cannot show). `build_deck(..., sidecar=False)` leaves them out.
- **Serve** (`server.py`): the deck is built without the sidecar, with `serve.notes` in the deck JSON (outside the hash) and KaTeX always included. `GET /__lattice/notes` gives every slide's sidecar Markdown, HTML and problems; `POST` with `{slide, md}` (JSON only, same origin only, 1 MB at most) rewrites that section and answers it rendered. The sidecar is never a rebuild trigger: a save bumps a notes version, and the live reload stream sends `notes` instead of `reload`; an edit made in an editor is noticed by the watcher (its own writes are not) and sent the same way. The page's live reload script turns `notes` into a `lattice:notes` event, on which every window refetches.
- **Presenter view** (`lattice.js`, `lattice.css`): the Notes heading gets an **Edit** button and a status line; the notes show the static notes, then the sidecar notes, alike. Edit (or a double-click on the notes) opens a textarea of the slide's sidecar Markdown under the static notes; typing saves after 700 ms and on closing (Escape, Done, focus leaving); saves run in order; the status says `saved`, the problems (an unknown link, say) or `not saved: ...`. Keys typed there never reach the deck. A slide change while editing (the other window, a click) saves to the slide the text was typed for, then edits the new slide's notes. The touch notes sheet shows both kinds.
- **Fixed on the way**: a fenced code block in static notes left a placeholder (`\x00C1\x00`) in the presenter panel and registered a runtime instance that was never mounted. Notes now draw code blocks themselves, as the `code` component draws them at rest (`lang`, `highlight`, `linenos`, `title`, `markers`, `line_base`); a component in notes is shown as code with LT068.
